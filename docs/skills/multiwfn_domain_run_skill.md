# Skill: Multiwfn domain analysis runner to VESTA

## When to use

Use `domain-run` when the input is an existing scalar cube/grid file and the
goal is to isolate connected spatial domains by a threshold criterion, then
view the selected domain in VESTA.

Good inputs include ABACUS density/potential/ELF cubes and cubes generated by
`multiwfn2vesta grid-run`.  This is cube post-processing; it does not require
a Molden wavefunction if the target scalar field is already in a cube.

## Command

```bash
multiwfn2vesta domain-run density.cub domain_products \
  --criterion '<0.5' \
  --domain-index 1 \
  --timeout 300
```

`--criterion` is forwarded to Multiwfn domain analysis and must start with
`<` or `>`, for example `<0.5` or `>0.001`.  `--domain-index` selects which
clustered domain is exported by Multiwfn post-processing options `10` and
`11`.

## Command Stream

The maintained stream is:

```text
200
14
3
<criterion>
-1
10
<domain_index>
11
<domain_index>
0
0
q
```

`200` enters Multiwfn other functions part 2, `14` enters domain analysis,
`3` sets the domain definition, `-1` yields domains from the current grid data
already loaded from the input cube, `10` exports `domain.cub`, and `11`
exports boundary grids to `domain.pdb`.

## Outputs

- `multiwfn_domain_input.txt`
- `multiwfn_domain.stdout.txt`
- `multiwfn_domain.stderr.txt`
- `multiwfn_domain_raw/domain.cub`
- `multiwfn_domain_raw/domain.pdb`
- `<stem>_domain.cub`
- `<stem>_domain.pdb`
- `multiwfn_domain_recipe.md`
- `<stem>_domain_cube.vesta`
- `<stem>_domain_cube_vesta_recipe.md`

## VESTA preset

`cube-preset domain` is a single positive isosurface preset for binary
`domain.cub`.  Multiwfn writes `1` for grids inside the selected domain and
`0` elsewhere, so the default isosurface is `0.5`.  Aliases are
`domain-cube`, `domain-analysis`, and `binary-domain`.

```bash
bin/multiwfn2vesta domain-run \
  /mnt/g/work/multiwfn2vesta/smoke/multiwfn_grid_run_smoke_20260610_h2o_density/products/h2o_density.cub \
  /mnt/g/work/multiwfn2vesta/smoke/multiwfn_domain_run_smoke_20260610/h2o_density \
  --criterion '<0.5' \
  --domain-index 1 \
  --stem h2o_density \
  --timeout 300
```

The run returned `0` and generated `h2o_density_domain.cub`,
`h2o_density_domain.pdb`, `h2o_density_domain_cube.vesta`, and the VESTA
recipe without launching the VESTA UI.

## Caveats

- The runner assumes the input cube loads as Multiwfn's current grid data.
  This is the tested and maintained path.
- `domain.pdb` contains boundary grid points, not a polished atom/CP layer.
  Use it as raw geometry evidence or a later overlay source.
- Multiwfn assigns domain indices after clustering.  If the selected
  `--domain-index` does not exist, inspect `multiwfn_domain.stdout.txt` and
  rerun with a valid index.
